# ADR-0001：同仓库绞杀迁移（neomd），而非原地重构或另开仓库

- 状态：已确认（2026-08-27，grilling 收敛）
- 决策者：项目维护者
- 关联：[v2 迁移计划](../v2-migration-plan.md)

## 背景

架构评审发现 v1 的结构性问题：约束类型知识在 `restraints/constructor.py` 与 `reporter.py` 双分发；可变 Box config 穿透所有层并被运行期回写（`neosystem.py:122` 的 fgroup）；构造即物理（`BasePipeline.__init__` 读盘+建 Context+占 GPU）；物理内核与策略焊死；`qmmm/engine/qmmm_engine.py` 因 import 笔误整个模块不可加载却无人发现（全仓仅 3 个端到端测试）。v2 设计方案（冻结 Plan + KernelPort seam + 知识三元组注册）与 v1 核心结构方向相反。

## 决策

**同一仓库内并行建立 `src/neomd/` 新包，绞杀者模式迁移；parity 全功能对齐后翻转，回收 `neomd` 包名。**

## 否决的替代方案

### 原地渐进重构

- v1 没有测试安全网（仅 3 个 e2e 需溶剂化体系 + CUDA），渐进扭转无验证依托
- v2 脊柱（冻结 Plan / KernelPort）与 v1 核心（可变 Box / 带策略 Engine）方向相反，中间态需同时养活两套范式数月
- 每次对 `modify_config` 的修补都是在给要拆的墙刷漆

### 另开新仓库

- 真正难重写的是资产（体系构建流程、力场处理、约束表达式里的物理），它们**可搬运而非重写**；需真正重写的核心仅 ~1.5k 行
- 同仓库保留 issues、CI、pixi 配置、示例、git 历史；切换日 = 一次大提交 + 版本跳变
- 年轻项目（v0.0.1、单人维护）不值得承担双仓库的 CI/发布/链接腐化成本

## 关键配套决策

- **硬冻结**（R3-Q1）：窗口期 v1 只修 bug——每新增一个 v1 特性都要搬两次并推迟翻转日
- **翻转判据是 parity 而非时间**（Q3/Q6）：不设时间上限，以 §6 parity 清单全绿为准
- **脊柱先行**（R3-Q2）：最小路径穿通整套架构后才批量铺功能
- **产物全新格式**（R3-Q3）：gethill/hills_ana 在翻转日断档，用户已认领，2.x 重写适配

## 后果

### 正面

- v1 全程可用、可发布 bugfix；用户无感知期
- 金样磁带与 CI 地基（Phase 0）在任何路线下都需要，零浪费
- 切换日清晰可回溯（tag `v1-final` + `neomd_legacy` 过渡）

### 负面（已认领）

- 双范式并存期的心智税；靠硬冻结与脊柱先行压缩
- 无时间盒 → 有拖延风险；parity 清单是唯一刹车
- 下游分析脚本（gethill/hills_ana）需重写适配新产物格式

## 重开条件

仅在以下情况重新审议本 ADR：v1 出现无法在冻结纪律下修复的紧急问题；或 parity 清单被证明存在无法对齐的项（如某 v1 行为本质上无法在新架构复现）。
