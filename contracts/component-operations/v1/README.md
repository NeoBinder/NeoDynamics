# Component operations private contract v1

This private NeoDynamics API stages exact input bytes, then runs one durable operation per user decision or scientific step. The host keeps review authorization. A request is an idempotent, owner-scoped command; its `request_id` is unique across all four component kinds. The worker runs once under the existing preparation lease and publication fence. Reconnect reads retained snapshots and artifacts without rerunning parameterization.

The API prefix is `/internal/md/v1/component-preparations`. `GET /catalog` reports method availability and limits. `POST /blob-uploads` registers a generic blob by exact SHA-256 and size; `PUT /blob-uploads/{upload_id}/content` stores its bytes. The two `GET /blob-uploads/...` routes return its receipt by ID or request ID. `POST /` submits a `ComponentRequest`; `GET /by-request/{request_id}` and `GET /{operation_id}` read its snapshot. `POST /{operation_id}/cancel` requests cancellation. Successful operations expose `GET /{operation_id}/inventory`, `GET /{operation_id}/qc`, and `GET /{operation_id}/artifacts/{artifact_id}/content`.

The request has `schema_version: 1`, `kind`, `request_id`, `inputs`, and kind-specific `options`. Each input gives a logical relative name, exact SHA-256 and byte count, and **either** an owner-scoped blob `upload_id` **or** a prior successful `operation_id` plus `artifact_id`. The service verifies same-owner access, the referenced digest and size, and prior producer receipt before admitting work. It materializes inputs beneath a private directory, reserving `index.json` for the hash map. Names are slash-separated lowercase safe segments, with no dot-leading segments, traversal, or duplicate names. No client path or executable code enters a request.

`component_review` binds `review_authorization_sha256` to a supplied, host-authorized decision record. `component_generate` chooses `gaff2` or `openff-sage-2.2.1` with a seed, or the bounded `amber-ff14sb-phosaa14sb-sep` method with exact `source_residue_id`, `template_id: "SEP"`, and pinned `template_resource_sha256`. The latter requires the prior successful Review's `state.json` and `instance.json` plus the exact reviewed `source.json.gz` blob; it retains SEP within one protein-chain instance. The `amber-ff14sb` general-protein method remains unavailable. `component_import` uses `declarative`; `component_assemble` uses `stored-package-v1`. The exact scientific state, recipe, input asset bytes, and physics are named inputs, not free-form options. The catalog must mark a method unavailable until its service implementation and qualification are accepted.

An operation snapshot contains the immutable request and request hash, state, revision, and either terminal receipt or error. The receipt pins resolved owner and input identities, prior producer receipt hashes, result digest, verification report digest, and artifact digests. Inventory adds safe relative artifact names. QC is a bounded summary with a report digest; full evidence remains an artifact. Blob uploads use `schema_version: 3` and `format: component-blob`, distinct from protein and topology source uploads.

The schemas are JSON Schema Draft 2020-12. Positive and negative examples live in `fixtures/`. Canonical request hashing uses RFC 8785 via `neomd_server.contract.content_hash`.
